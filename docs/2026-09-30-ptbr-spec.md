# Portuguese (pt-BR) — spec (planned 2026-09-30, not implemented yet)

Add Brazilian Portuguese as a second language, with every text behind a key so
wording is easy to change or add later. Code and docs stay in English.

## Decisions

- **Default language:** follow the phone (`pt*` → pt-BR, anything else →
  English). Settings → Language: Automatic / English / Português.
- **Switching in the intro:** a 🇧🇷 and a 🇺🇸 flag at the top left of the
  intro's first screen.
- **Sample data** (Developer section) stays in English.
- **Docs** (Guide, Testing, specs) stay in English; code always in English.
- **Translations are reviewed first** in a private review page
  (https://claude.ai/artifact/1LRc9nvCDafGzL55we8XHV). Pedro edits the
  Portuguese, answers the flagged questions and marks rows OK; his edits are
  stored with the page and read back before building `pt-BR.ts`. The starting
  catalog (keys, English, suggestions, questions) is `docs/i18n/catalog.json`.

## What makes it more than swapping words

1. Text lives in screens *and* in the logic that writes sentences (Insights,
   Review, Today, intro).
2. Sentences built from pieces need per-language plurals and word order.
3. Gender agreement: meta (f) vs projeto (m); status words avoid it
   (em dia / com atraso / em risco).
4. Dates ("30 de setembro", "amanhã") and decimal commas (7,5 h).
5. Plan-change history is stored as English text ("gym target", "4× per
   week") and Insights/Review match on it. New revisions must be stored
   language-neutral; old ones keep being read.
6. The "is it checkable?" rule looks for English words; add Portuguese ones
   (key `check.words`) and accept both lists in either language.
7. Intro content (areas, examples, values, preps, placeholders, note) is
   adapted, not just translated.
8. User data (titles, values, reasons) is never translated.
9. Portuguese runs 20–30% longer: check tabs, segmented controls, chips,
   pills and chart legends at phone width.
10. Tests keep running in English; tricky pt-BR formatting gets its own tests.

## Architecture

- `src/i18n/en.ts` is the source of truth, grouped by screen (the catalog's
  key prefixes). `src/i18n/pt-BR.ts` has the same shape; TypeScript fails the
  build if a key is missing or extra.
- Entries are plain strings, or small functions for anything with numbers,
  plurals or word order: `weekProgress: (n, total) => …`. No ICU syntax, no
  library.
- A formatting module owns month and weekday names, relative days, decimals
  and plurals.
- Screens read texts through a hook; the logic reads the current language the
  same way. Tests default to English.
- The setting lives on the device (`settings.language`); switching re-renders
  at once, no reload. `<html lang>` follows it.
- README gets a short "how to edit text" note; a test flags English typed
  straight into a screen.

## Phases

1. Move all English into `en.ts` (no visible change).
2. Neutral plan-change history, Portuguese words in the checkable rule, date
   and number formatting.
3. Build `pt-BR.ts` from the reviewed catalog.
4. Language setting, intro flags, Portuguese intro content, layout pass in
   Portuguese at phone width.
5. Docs and tests.
